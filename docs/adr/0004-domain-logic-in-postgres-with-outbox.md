# Domain logic lives in Postgres; Edge Functions only send

Business rules live in the database: multi-row operations (taking a Dose and reducing stock, recording a Stock Count, editing an Appointment and bumping its invite sequence) are Postgres functions called as RPCs, and the per-minute pg_cron job generates Doses, marks Missed ones and enqueues due reminders in SQL. The client talks to Supabase directly under row-level security; there is no API layer of our own. Outbound I/O goes through an outbox table drained by one Edge Function that sends Web Push and invite emails and records results, with no domain rules of its own. We picked this over writing the rules in TypeScript (in Edge Functions or an API service) because it keeps every rule in one place with transactional guarantees, avoids cold starts and the functions' 2-second CPU limit, and gives a natural retry and failure record for sends. The trade-off is that much of the domain logic is written and tested in SQL rather than TypeScript.
